agmsg/tmux controller-worker 改修引き継ぎ計画

controller pane への自然文指示から、同一 tmux window 内の worker へ安全に委譲し、 通知、次 turn 処理、返信回収まで成立させるための修正計画。 別セッションで実装を引き継ぐため、背景、最終方針、実装対象、検証条件をまとめる。

結論

v1 は 同一 tmux window 限定 とする。 controller helper は source pane / source team が一意に確定できない場合に送信しない。 Codex では即時実行を約束せず、即時に保証するのは tmux 上の unread 通知までとする。

今回の問題は、controller が window3 の worker に送るつもりで、古い team を history や曖昧な identity 推定から選び、別 team の worker 宛に送ってしまったことにある。したがって、修正は transport だけでなく、 設計文書、skill 手順、hook 文言、tmux 表示、回帰テストまで一体で行う。

実用 UX

項目 採用する体験 不採用にする体験
ユーザー操作 controller pane に自然文で依頼する。 ユーザーが send.sh や tmux helper を直接実行する。
宛先指定 worker1、worker2、2:2、right などを同一 window 内で解決する。 別 window の pane を暗黙に選ぶ。
Codex delivery unread 通知は即時表示し、実処理は次 turn または明示的な受信確認で行う。 Claude Monitor 相当の即時処理を Codex で保証する。
controller 報告 宛先 identity、pane、request id、期待返信、未返信 timeout を説明する。 内部 helper command の文字列をユーザー向け手順として見せる。

修正方針

1. 設計文書を HTML に統一する

  • docs/agmsg-practical-ux-design.html を canonical な実用設計にする。
  • 古い agmsg/tmux の設計メモは HTML 側に統合し、混乱する旧仕様を残さない。
  • 役割メタデータという旧発想ではなく、identity、namespace、actas の語で統一する。

2. source pane 不明時は fail closed にする

  • controller workflow は history や whoami の複数候補から team を推定しない。
  • controller helper は source pane を明示できる経路を必須にする。
  • source pane / source team が一意に確定しない場合は送信しない。
  • 送信しなかった場合は、helper command ではなく「送信しなかった理由」「解決できた候補」「次に必要な操作」を自然文で返す。

3. cross-window 送信を禁止する

  • agmsg-tmux-send.sh の送信 team は常に source pane の team に固定する。
  • 2:2 や %pane が別 window を指す場合は fail closed し、send.sh を呼ばない。
  • 既存 isolated test の「別 window team に送れること」を期待する箇所は、危険挙動として期待値を反転する。

4. routing を監査可能にする

  • structured request に schema_version を追加する。
  • source_pane、source_team、target_pane、target_team を body に含める。
  • history から、どの pane / team 解決で送信されたかを後から確認できるようにする。

5. unread 通知を tmux 上に出す

  • DB を read-only poll する notification watcher を追加する。
  • pane title / sidebar に worker1 !1 from controller1 相当の unread summary を出す。
  • 通知 watcher は read_at を更新しない。
  • 閉じた pane、stale identity、別 window の membership は表示対象から外す。

6. Stop hook の誤既読化を防ぐ

  • Codex Stop hook / check-inbox.sh は pane identity が一意に確定した時だけ unread を読む。
  • 複数候補、fallback identity、tmux pane option 不明時は未読のまま残す。
  • worker workflow に渡すのは structured request だけにする。

7. Claude 向け hook 文言を日本語化する

  • AGMSG-DIRECTIVE と Monitor directive の説明文を日本語にする。
  • command、description、persistent など tool field 名は維持する。
  • directive 内に「このセッションでは日本語で応答すること」を明記する。
  • description: agmsg inbox stream は description: agmsg 受信監視 などに寄せる。

テスト計画

テスト 検出したい失敗 合格条件
cross-window rejection window1 controller から別 window の 2:2 / %pane に送れてしまう。 fail closed し、send.sh が呼ばれない。
wrong-team regression 古い team の同名 worker1 に誤配送する。 現在 window の worker は別 team message を処理せず、誤配送がログで検出される。
missing env regression TMUX_PANE や AGMSG_TMUX_CURRENT_PANE が無い状態で推定送信する。 controller send は送信せず、理由を返す。
Stop hook safety identity が曖昧なまま unread を既読化する。 read_at が付かず、未読のまま残る。
notification UX 送信済みだが tmux 上で通知が見えない。 pane title / sidebar に unread count と送信元が出る。
notification read safety 通知表示だけで message が既読になる。 watcher 実行後も read_at は更新されない。
next-turn delivery 正しい same-window team への request が次 turn で処理されない。 worker の次 turn で inbox context として request が出る。
directive language hook 注入文の英語により Claude が英語応答へ寄る。 emitted directive が日本語主体で、「日本語で応答」が含まれる。
document cleanup 旧仕様の設計文言が残り、次セッションが混乱する。 旧 Markdown 設計参照、旧 cross-window 期待値、旧称の混在が残らない。

完了前に ./lint.sh と .config/tmux/test-agmsg-tmux-scope-isolated.sh を必ず実行する。HTML は構文検証だけでなく、設計内容が旧仕様へ逆戻りしていないことを検索で確認する。

実装順序

  1. HTML 設計と agmsg skill 文書を先に直し、曖昧推定禁止と日本語 directive 方針を固定する。
  2. tmux helper の source pane 必須化と same-window 制約を実装する。
  3. Stop hook / check-inbox の誤既読防止を実装する。
  4. unread notification watcher と tmux 表示を実装する。
  5. Claude Monitor directive を日本語化する。
  6. 回帰テストを追加し、今回の事故パターンが失敗として検出されることを確認する。
  7. source-of-truth から generated/live へ反映し、lint と isolated test を通す。
